ConceitoResumos das fontes de context engineering

Anthropic — "Effective context engineering for AI agents"

Artigo técnico · publicado 29/set/2025
  • Context engineering é a evolução do prompt engineering: não é "as palavras certas", é "qual configuração de contexto gera o comportamento desejado".
  • O agente em loop gera cada vez mais dados — o contexto tem de ser refinado ciclicamente.
  • Estratégias: context retrieval + agentic search (busca sob demanda) e structured note-taking (o agente anota em memória externa).
  • Para tarefas longas: mantém só o estado atual e descarrega o histórico em notas.
Insight: "não faça do prompt o sistema de memória" — guarde fora do modelo e injete só o necessário.

Weaviate — "Context Engineering" (6 pilares)

Artigo · Weaviate (base vetorial)
  • A janela de contexto é um recurso escasso (como um whiteboard que enche e apaga o velho).
  • Diferença entre demo bonito e sistema de produção é como a informação é selecionada/entregue a cada passo.
  • 6 pilares: Memory, Selection, Compression, Contextual retrieval, Multi-step reasoning, State management.
  • Combina janela de contexto com memória de longo prazo (vector store) e decidir o que entra.
Insight: trate a janela como orçamento de atenção — gaste só em tokens de alto sinal.

MindStudio — "9 Components of an Agentic OS"

Artigo · MindStudio
  • Um agentic OS é um padrão de componentes, não um produto.
  • Os 9: identity file, short-term memory, long-term memory, skills, planning layer, orchestration, handoff protocols, evaluation, guardrails.
  • Cada agente tem memória curta (contexto ativo) + longa (compartilhada em vector store) e busca semântica.
Insight: use os 9 como checklist do projeto — é o esqueleto da nossa arquitetura.

Augment Code — "Agent Memory vs. Context Engineering"

Guia · Augment Code
  • Memória = armazenamento externo que sobrevive à sessão (arquivos, DB, vector store).
  • Context engineering = selecionar/comprimir/injetar o que entra na janela finita.
  • 3 camadas de persistência: context files (AGENTS.md, regras), agent memory (decisões com curadoria humana), living specs (intenção que evolui).
  • Memória sem context engineering vira "acumulo"; context engineering sem memória vira amnésia.
  • Mitigação: revisar memórias no fim da sessão (aprovar/editar/descartar).
Insight: a curadoria humana das memórias é o que evita contexto obsoleto contaminando o agente.

Mão na massaResumos dos frameworks

Letta (antigo MemGPT) — site e pesquisa

Site oficial + blog de pesquisa
  • Criado pelos autores do MemGPT (UC Berkeley Sky Computing Lab).
  • "Machines that learn" — agentes que lembram tudo, aprendem continuamente.
  • Conceitos-chave do blog: Memory Models (RL com memória), Context Constitution, Context Repositories (memória versionada via git), Sleep-time Compute (raciocina em idle, não na inferência), Continual Learning em token space.
  • Produto: Letta Agent — memória, identidade e capacidades evoluem com a experiência.
Insight: a ideia de "sleep-time compute" é o agente organizar a própria memória enquanto ocioso — aplicável à nossa camada 4.

A-MEM — Agentic Memory for LLM Agents (paper)

Paper arXiv:2502.12110 · NeurIPS 2025
  • Sistema de memória que se organiza sozinho, seguindo o método Zettelkasten.
  • Ao adicionar memória: gera nota com contexto, keywords e tags; procura memórias históricas relacionadas e cria links.
  • Memória "evolui": novas memórias podem atualizar representações das antigas.
  • Rede de conhecimento interconectada, adaptável e consciente de contexto.
  • Supera baselines SOTA em 6 modelos de base.
Insight: é a materialização técnica dos "insights acumulativos" (camada 4) — aprendizado que se conecta.

AIOS — AI Agent Operating System (repo)

GitHub · agiresearch/AIOS · 6.2k stars · 859 commits
  • "LLM as OS, Agents as Apps" — trata agents como processos gerenciados pelo SO.
  • Tem scheduler, gerenciamento de memória e contexto para múltiplos agents.
  • Inclui aios-rs (versão Rust) e documentação em docs.aios.foundation.
  • Papers de base: A-Mem, LiteCUA (computer-use), semantic file system, Cerebrum SDK.
Insight: referência mais próxima de um "SO de verdade" para IA — use como modelo de orquestração quando crescer.

Vídeo "How to Build Your Own AI Operating System"

YouTube · arquitetura full-stack
  • Quebra a arquitetura em 3 camadas: webhook triggers, scheduled workflows, agent layer.
  • Stack: Python/FastAPI (backend), Celery (filas), Redis (estado), Docker (deploy).
  • Foco em como disparar, agendar e orquestrar agents de forma confiável.
Insight: a separação trigger / scheduler / agent é um bom ponto de partida prático para nosso backend.

Vídeo "I Built an AI Agent Operating System in 90 Days"

YouTube · relato prático
  • Apresenta uma "company context layer" que dá a cada agente "memória".
  • Mostra como construir uma camada de memória/contexto para a organização.
  • Aborda o que funciona (e o que não) ao escalar agents num prazo real.
Insight: a "context layer" dele espelha o G4 OS — memória compartilhada é o que dá coerência ao sistema.

Vibe codingResumos das ferramentas

Comparativo Claude Code vs Codex vs Lovable vs Replit

XDA Developers + complemento (justinmckelvey.com, 2026)
  • Claude Code (terminal): melhor disciplina de "ficar no escopo" — edita só o que pediu. Ótimo para refatoração e revisão. Modelo padrão Claude Sonnet 4.6.
  • Codex (terminal, OpenAI): mais autônomo/agressivo — termina trabalho em massa (renomear em 47 arquivos, migrações) mas gera diffs grandes.
  • Lovable (browser): mais polido para não-devs (React+Tailwind+Supabase, hosting incluso). Stack opinativo, difícil de mudar.
  • Replit (browser): Linux real na nuvem com armazenamento persistente — bom para colaboração e protótipos.
  • Modelo importa mais que interface: "escolha o cérebro, depois a carcaça".
Insight: pra nosso OS, Claude Code/Codex para lógica + Lovable para a UI — e os dois sincronizam via GitHub.

Reddit — "Build Lovable for Claude Code users. No Costs."

Thread r/ClaudeAI
  • Usuários combinam Lovable (gera a estrutura/app) com Claude Code (lógica, integrações, Stripe, etc.).
  • Uso de GitHub sync para manter tudo versionado e evitar divergência entre ferramentas.
  • Claude Code "one-shots" projetos que custariam caro no Lovable; Lovable faz a parte visual.
Insight: o fluxo "Lovable cria, Claude Code conecta" é exatamente o nosso modo de construir com vibe coding.
