Documentação e base de estudosO que é um AI OS

Este repositório documenta o estudo e a construção de um AI OS (sistema operacional de IA) pessoal. Ele funciona como base de referência: registra o que está sendo aprendido e serve de ponto de partida para a implementação.

Um AI OS não é um produto pronto — é uma arquitetura. É o conjunto de camadas que transforma um modelo de linguagem, que sozinho não lembra nada entre sessões, em um sistema com identidade, memória e estado persistente.

Arquitetura de um AI OS

O fluxo abaixo mostra como as peças se conectam. A seta central é a camada de contexto — o que decide, a cada momento, o que o modelo "sabe".

Contexto é rei. O modelo não "sabe" de nada por padrão. Tudo depende do que é carregado na janela dele e de como isso é acumulado ao longo do tempo. Por isso a camada de contexto — não o modelo em si — é o coração de um AI OS.

Camadas em detalhe

1

Contexto ativo

O que está "na tela" do modelo agora: a tarefa, as instruções e as últimas mensagens. É volátil e limitado em tamanho.

2

Memória de curto prazo

A "RAM" do agente: mantém o estado da tarefa em andamento, o que foi feito e o que falta. Some quando a tarefa termina.

3

Memória de longo prazo

Sobrevive entre sessões. Armazena preferências, fatos, decisões e histórico em arquivos ou base vetorial.

4

Insights acumulativos

Memória que se organiza sozinha (ex.: método Zettelkasten). Conecta aprendizados e melhora com o uso.

5

Orquestração

Como o sistema recebe uma intenção e a transforma em passos: planeja, chama ferramentas e coordena agentes.

6

Conexões

Integrações com sistemas externos (e-mail, planilhas, bancos de dados, APIs) que dão "corpo" ao OS.

Passo a passo para construir

Roteiro de estudo e implementação, na ordem sugerida. Cada etapa aponta para o material correspondente mais abaixo.

1

Entender a tese (G4 OS)

Consumir o podcast "O Jogo da IA" e o material do Tallis Gomes para internalizar o conceito de sistema operacional de IA conectado à empresa. → Fontes G4 OS

2

Estudar context engineering

Ler a documentação da Anthropic e da Weaviate sobre como montar e gerenciar a camada de contexto. → Conceito

3

Mapear os 9 componentes

Usar o checklist do MindStudio (identidade, memórias, skills, planejamento, orquestração, guardrails) como esqueleto do projeto. → Conceito

4

Escolher a base de memória

Avaliar Letta (agentes stateful), A-MEM (memória que evolui) e AIOS (LLM como SO) como fundação técnica. → Mão na massa

5

Montar o primeiro agente

Subir um agente com memória persistente usando os frameworks open source e validar a retenção entre sessões. → Mão na massa

6

Conectar sistemas externos

Integrar planilhas, e-mail ou APIs para o OS "enxergar" dados reais, como no G4. → Referência G4 OS

7

Construir com vibe coding

Usar Claude Code / Codex / Lovable para escrever o código a partir de descrições em linguagem natural. → Vibe coding

8

Iterar e documentar

Registrar decisões, arquitetura e aprendizados neste repositório, mantendo a base de estudo atualizada.

FundamentoConceito — contexto é rei e arquitetura de memória

  • Anthropic — "Effective context engineering for AI agents"
    Texto obrigatório. Manual prático de como montar a camada de contexto: recuperação, "note-taking" do agente e memória persistente fora da janela de contexto.
    ENartigo técnico
  • Weaviate — "Context Engineering" (os 6 pilares)
    Desenho completo combinando janela de contexto com memória de longo prazo (base vetorial) e seleção do que entra a cada passo.
    ENartigo
  • MindStudio — "9 Components of an Agentic OS"
    O "mapa de arquitetura": identity file, short-term memory, long-term memory, skills, planning, orchestration, handoff, evaluation e guardrails. Use como checklist do seu projeto.
    ENartigo
  • Augment Code — "Agent Memory vs. Context Engineering"
    Esclarece as 3 camadas de persistência (context files, agent memory, living specs) e a diferença entre "memória" e "engenharia de contexto".
    ENguia

PráticaMão na massa — construir o seu OS

  • Letta (antigo MemGPT) — site
    Framework open source de agentes stateful que lembram tudo. Caminho mais direto para ter memória persistente rodando.
    open sourceGitHub
  • A-MEM — Agentic Memory for LLM Agents (paper)
    Sistema de memória que se organiza sozinho (método Zettelkasten). A referência técnica de "memória que evolui" — seu conceito de insights acumulativos.
    paper + códigoGitHub
  • AIOS — AI Agent Operating System (repositório)
    Implementação real de "LLM como SO": gerencia agents como processos, com scheduler, memória e contexto. Veja código de um OS de IA funcionando.
    open source
  • "How to Build Your Own AI Operating System" (vídeo)
    Quebra a arquitetura em 3 camadas (webhook triggers, scheduled workflows, agent layer) com FastAPI/Celery/Redis/Docker. Mão na massa pesada.
    vídeo
  • "I Built an AI Agent Operating System in 90 Days" (vídeo)
    Relato prático com "company context layer" dando memória aos agents.
    vídeo
