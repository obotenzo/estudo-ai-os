Ponto de partidaO que é um "AI OS"

Um AI OS (sistema operacional de IA) não é um produto — é uma arquitetura. É o conjunto de camadas que faz um modelo de linguagem deixar de ser "uma caixa que responde" e passar a ter identidade, memória e estado persistente.

O princípio central, repetido por quem está na frente disso, é simples: contexto é rei. O modelo por si só não lembra nada entre sessões. Quem decide o que ele "sabe" a cada momento é a camada de contexto — o que você carrega na janela dele, de onde vem, e como é acumulado ao longo do tempo.

Os pilares que aparecem em toda implementação séria:

  • Memória de curto prazo — o contexto ativo da tarefa atual (a "RAM" do agente).
  • Memória de longo prazo — o que persiste entre sessões (arquivos, base vetorial, notas).
  • Insights acumulativos — a memória que evolui sozinha, organizando o que foi aprendido.
  • Orquestração — como os agentes recebem tarefas, raciocinam e agem.

Como referência prática, este material usa o G4 OS (do Tallis Gomes / G4): um sistema que conecta CRM, ERP, planilhas e Slack, "enxerga a empresa" e distribui tarefas a partir de uma conversa. A ideia aqui é estudar essa tese e construir a sua própria versão — com vibe coding (descrever o que quer em linguagem natural e deixar a IA escrever o código).

FundamentoConceito — contexto é rei e arquitetura de memória

  • Anthropic — "Effective context engineering for AI agents"
    Texto obrigatório. Manual prático de como montar a camada de contexto: recuperação, "note-taking" do agente e memória persistente fora da janela de contexto.
    ENartigo técnico
  • Weaviate — "Context Engineering" (os 6 pilares)
    Desenho completo combinando janela de contexto com memória de longo prazo (base vetorial) e seleção do que entra a cada passo.
    ENartigo
  • MindStudio — "9 Components of an Agentic OS"
    O "mapa de arquitetura": identity file, short-term memory, long-term memory, skills, planning, orchestration, handoff, evaluation e guardrails. Use como checklist do seu projeto.
    ENartigo
  • Augment Code — "Agent Memory vs. Context Engineering"
    Esclarece as 3 camadas de persistência (context files, agent memory, living specs) e a diferença entre "memória" e "engenharia de contexto".
    ENguia

PráticaMão na massa — construir o seu OS

  • Letta (antigo MemGPT) — site
    Framework open source de agentes stateful que lembram tudo. Caminho mais direto para ter memória persistente rodando.
    open sourceGitHub
  • A-MEM — Agentic Memory for LLM Agents (paper)
    Sistema de memória que se organiza sozinho (método Zettelkasten). A referência técnica de "memória que evolui" — seu conceito de insights acumulativos.
    paper + códigoGitHub
  • AIOS — AI Agent Operating System (repositório)
    Implementação real de "LLM como SO": gerencia agents como processos, com scheduler, memória e contexto. Veja código de um OS de IA funcionando.
    open source
  • "How to Build Your Own AI Operating System" (vídeo)
    Quebra a arquitetura em 3 camadas (webhook triggers, scheduled workflows, agent layer) com FastAPI/Celery/Redis/Docker. Mão na massa pesada.
    vídeo
  • "I Built an AI Agent Operating System in 90 Days" (vídeo)
    Relato prático com "company context layer" dando memória aos agents.
