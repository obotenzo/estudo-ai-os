Mão na massa

As fundações técnicas para construir seu AI OS com memória persistente: Letta, A-MEM e AIOS — todos open source.

FundaçãoEscolhendo a base de memória

Um AI OS precisa de uma camada de memória que sobreviva entre sessões e se mantenha organizada. Três projetos open source cobrem isso hoje, cada um com um ângulo diferente. Role para baixo para decidir por onde começar.

L

Letta (MemGPT)

Agentes stateful que lembram tudo. Abstrai a complexidade da memória para você focar em lógica.

A

A-MEM

Memória que evolui sozinha (método Zettelkasten). Conecta aprendizados automaticamente.

O

AIOS

LLM como SO: gerencia agents como processos, com scheduler, memória e contexto.

ResumosLetta, A-MEM, AIOS e vídeos

  • Letta — site oficial
    "Machines that learn." Cria agentes stateful que lembram tudo, aprendem continuamente e melhoram com o tempo.
    Resumo do conteúdo (site + blog de pesquisa)

    A Letta é um laboratório de IA de San Francisco, fundado pelos criadores do MemGPT (oriundos do Sky Computing Lab da UC Berkeley, o mesmo berço do Spark e do Ray). A proposta é "máquinas que aprendem" — agentes experienciais que lembram tudo, aprendem continuamente e melhoram a si mesmos com o tempo. O blog de pesquisa revela os conceitos que sustentam esse modelo: Memory Models (treinados com RL nativo de memória), Context Constitution (princípios que governam como o agente gerencia contexto para aprender com a experiência), Context Repositories (memória versionada via git), Sleep-time Compute (o agente raciocina sobre o contexto enquanto está ocioso, não durante a inferência) e Continual Learning em token space (aprender no espaço de tokens é a chave para agentes que realmente evoluem). O produto concreto é o Letta Agent, cuja memória, identidade e capacidades evoluem com a experiência — e é exatamente esse comportamento de "organizar a própria memória enquanto ocioso" que se aplica à nossa camada 4.

    Insight: a ideia de "sleep-time compute" é o agente organizar a própria memória enquanto ocioso — aplicável à nossa camada 4.
  • Letta — repositório GitHub
    Código aberto (antigo MemGPT), centenas de contribuidores. Implementa o design de memória de longo prazo em LLMs.
    Resumo do conteúdo (repositório)

    O repositório da Letta (antigo MemGPT) é o código aberto por trás do sistema, com centenas de contribuidores e implementação do design de memória de longo prazo para LLMs. Roda localmente e abstrai a complexidade de gerenciar memória — separando memória arquivada (longo prazo) da memória de trabalho (contexto ativo), exatamente as camadas 2 e 3 do nosso diagrama. Por ser open source e bem mantido, é o caminho mais direto para subir um agente stateful com memória persistente (etapa 5 do nosso passo a passo) sem ter que construir a camada de memória do zero.

    Insight: é o caminho mais direto (etapa 5) para ter um agente com memória rodando.
  • A-MEM — paper (arXiv:2502.12110)
    Sistema de memória agentica que organiza memórias dinamicamente. Baseado no método Zettelkasten de notas conectadas.
    Resumo do conteúdo (paper, NeurIPS 2025)

    O A-MEM (Agentic Memory for LLM Agents) é um sistema de memória que se organiza autonomamente, seguindo os princípios do método Zettelkasten — a técnica de notas interconectadas usada por pesquisadores para construir redes de conhecimento. Quando uma nova memória é adicionada, o sistema gera uma nota com múltiplos atributos estruturados (descrição de contexto, keywords e tags) e, em seguida, analisa as memórias históricas para identificar conexões relevantes, criando links onde há similaridade. O ponto mais interessante é a "evolução" da memória: conforme novas memórias são integradas, elas podem disparar atualizações nas representações e atributos das memórias antigas, permitindo que a rede refinie continuamente sua compreensão. Nos experimentos, o método superou baselines de estado da arte em seis modelos de base. É a materialização técnica dos nossos "insights acumulativos" (camada 4): uma memória que não apenas empilha fatos, mas os conecta e melhora com o uso.

    Insight: é a materialização técnica dos "insights acumulativos" (camada 4) — aprendizado que se conecta.
  • A-MEM — repositório GitHub
    Código aberto do paper. Boa referência para quem quer implementar "insights acumulativos" (camada 4).
    Resumo do conteúdo (repositório)

    O repositório agiresearch/A-mem contém o código aberto do paper A-MEM, permitindo implementar na prática a memória que evolui e se conecta sozinha. É a referência concreta para quem quer construir a camada 4 do nosso OS (insights acumulativos) sem reinventar a técnica do zero. Estudar este código ajuda a entender como estruturar notas com atributos, como buscar conexões semânticas e como propagar atualizações entre memórias — o comportamento que faz o sistema "ficar mais esperto" conforme é usado, alinhado à tese do G4 de um contexto que cresce.

    Insight: estudar este repo ajuda a construir a memória que "fica mais esperta" com o uso.
  • AIOS — repositório GitHub
    Implementação real de "LLM como SO": gerencia agents como processos, com scheduler, memória e contexto. Veja código de um OS de IA funcionando.
    Resumo do conteúdo (repositório, 6.2k stars, 859 commits)

    O AIOS (AI Agent Operating System) parte do conceito "LLM as OS, Agents as Apps" — trata os agentes como processos gerenciados por um sistema operacional, com um scheduler, gerenciamento de memória e controle de contexto para múltiplos agents rodando ao mesmo tempo. O repositório (com quase 6,2 mil estrelas e centenas de commits) inclui até uma versão em Rust (aios-rs) e documentação em docs.aios.foundation, além de papers de base como A-Mem, LiteCUA (computer-use) e um semantic file system. É a referência mais próxima de um "SO de verdade" para IA que existe em código aberto, e serve como modelo de orquestração em nível de sistema quando o nosso projeto crescer além de um único agente.

    Insight: referência mais próxima de um "SO de verdade" para IA — use como modelo de orquestração quando crescer.
  • "How to Build Your Own AI Operating System" (vídeo)
    Quebra a arquitetura em 3 camadas (webhook triggers, scheduled workflows, agent layer) com FastAPI/Celery/Redis/Docker. Mão na massa pesada.
    Resumo do conteúdo (vídeo, arquitetura full-stack)

    Neste vídeo, o autor detalha a arquitetura de um AI OS próprio dividida em três camadas: webhook triggers (gatilhos externos que disparam o sistema), scheduled workflows (fluxos agendados que rodam no tempo certo) e o agent layer (onde os agentes de IA efetivamente raciocinam e agem). A stack usada é Python com FastAPI no backend, Celery para filas de tarefas, Redis para estado e Docker para deploy. O foco está em Como disparar, agendar e orquestrar agents de forma confiável, em vez de apenas "fazer um chatbot". Para o nosso projeto, a separação entre trigger / scheduler / agent é um bom ponto de partida prático para o backend: permite que o OS reaja a eventos e também execute tarefas recorrentes de forma previsível.

    Insight: a separação trigger / scheduler / agent é um bom ponto de partida prático para nosso backend.
  • "I Built an AI Agent Operating System in 90 Days" (vídeo)
    Relato prático com "company context layer" dando memória aos agents — espelha a ideia do G4 OS.
    Resumo do conteúdo (vídeo, relato prático)

    O vídeo relata, em tom de bastidores, como o autor construiu um sistema operacional de agentes de IA em 90 dias, com destaque para uma "company context layer" (camada de contexto da empresa) que dá a cada agente uma espécie de memória compartilhada. A ideia é que todos os agents enxerguem o mesmo contexto organizacional — decisões, estado de projetos e conhecimento acumulado — em vez de cada um operar isolado. O autor também aborda o que funcionou e o que não funcionou ao escalar agents num prazo real, o que é valioso como "lição de campo". Essa camada de contexto espelha diretamente o G4 OS: a memória compartilhada é o que dá coerência ao sistema como um todo, fazendo com que os agents atuem como uma operação única e não como caixas isoladas.

    Insight: a "context layer" dele espelha o G4 OS — memória compartilhada é o que dá coerência ao sistema.
